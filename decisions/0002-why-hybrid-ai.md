# ADR-0002 · Why Hybrid AI (Claude + 자체 Qwen)?

- **Status**: Accepted
- **Date**: 2026-03-05
- **Last updated**: 2026-05-23
- **Decision driver**: 책임개발자 (김민구)

## Context

HMS의 AI 기능은 두 가지로 갈라진다:

1. **병원 규칙 Q&A 챗봇** (DOCTOR · NURSE 대상): 병원 내부 규정·진료 절차·매뉴얼에 대한 자연어 질의응답. 입력·출력 모두 **공개해도 무방한** 운영 정보.
2. **증상 분석 · 의료 상담 추천** (비회원 환자 대상): 환자가 입력한 증상 텍스트로 진료과·의사를 추천. 입력 자체가 **개인 의료 정보**(증상·체질·복용 약 등).

품질·비용·프라이버시 트레이드오프:
- 외부 API(Claude): 응답 품질 ↑, 비용 토큰당, **외부 전송** 위험 (의료 정보)
- 자체 호스팅(Qwen 2.5 + RAG): 외부 전송 없음, 운영비 GPU 고정, 품질은 도메인 튜닝에 따라

대안 검토:
1. **모두 Claude로**: 품질 최고, 그러나 의료 정보 외부 전송이 PHI 규제 측면에서 위험.
2. **모두 자체 호스팅**: 프라이버시 안전, 그러나 공개 규칙 Q&A 같은 단순 작업에도 자체 LLM 운영비를 들임.
3. **하이브리드**: 민감도 기준으로 LLM을 분기.

## Decision

**LLM Service가 라우터 역할을 하는 하이브리드 AI**를 채택한다.

- **공개 규칙 Q&A** → Claude API. 운영 매뉴얼·진료 규정 등 외부 공개 가능한 정보만 전송.
- **증상 분석 · 의료 상담** → 자체 호스팅 Python LLM 서버 (FastAPI + Qwen 2.5 + ChromaDB RAG). 외부 전송 0.
- 라우팅 결정은 컨트롤러 메서드에서 명시적 분기, 우연한 잘못된 LLM 호출을 방지.

## Consequences

**받아들이는 이점**
- 비용·품질·프라이버시 3개 축을 동시에 최적화. 단일 LLM 선택에서는 불가능.
- LLM Service가 명시적 분기를 가지므로 새로운 AI 기능 추가 시 의사결정이 강제로 명시화됨.
- 자체 호스팅 LLM은 ChromaDB RAG로 병원 도메인에 특화되어, 일반 챗봇보다 정확도가 높음.

**받아들이는 비용**
- LLM 인프라가 두 개로 운영됨 (Claude API 키 관리 + 자체 LLM 서버 운영).
- LLM Service에 분기 로직이 모이므로 이 클래스의 변경 비용이 상대적으로 큼.
- 자체 호스팅 LLM의 응답 품질이 Claude 대비 떨어질 수 있어, 증상 추천 정확도 모니터링이 필수.
